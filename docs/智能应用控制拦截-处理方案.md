# Yuhub 被「智能应用控制」拦截 —— 原因与处理方案

> 现象（用户实测截图）：打开 `Yuhub.exe` 弹出
> 「智能应用控制已阻止可能不安全的应用 … 无法验证其发布者」。
> 这不是杀毒报毒，也不是文件坏了，而是 Windows 11 的
> **智能应用控制（Smart App Control，SAC）** 在拦未签名的程序。

---

## 一、先分清是「谁」拦的（很重要）

Windows 上有三道不同机制，处理方式完全不同：

| 机制 | 弹窗长什么样 | 能不能放行 |
|---|---|---|
| **Smart App Control（SAC）** | 「智能应用控制已阻止可能不安全的应用」 | **没有「仍要运行」、也没有按应用例外**，只能关或签名 |
| SmartScreen | 蓝色「Windows 已保护你的电脑」 | 有「更多信息 → 仍要运行」 |
| Defender 杀毒 | 「发现威胁 / 已隔离」 | 保护历史里可「允许在设备上」 |

**你截图里的是第一种（SAC）**。确认方法：
Windows 安全中心 → 病毒和威胁防护 → **保护历史记录**；
或事件查看器 → 应用程序和服务日志 → Microsoft → Windows → **CodeIntegrity → Operational** → 事件 **3077**（能看到被拦的具体文件）。

> 补充：SAC 只存在于 **Windows 11**（新装系统自带），Win10 没有。

---

## 二、处理方案（按使用场景选）

### 方案 A：关掉 SAC（最省事，推荐给"自己的 / 朋友的机器"）

1. `Win + I` 打开设置 → **隐私和安全性** → **Windows 安全中心** → 打开；
2. **应用和浏览器控制** → **智能应用控制设置**；
   （快捷键：`Win + R` 输入 `windowsdefender://smartapp/` 回车）
3. 选 **关闭**，确认警告；
4. **重启电脑** 后就能正常运行 Yuhub。

⚠️ 必须知道的代价与坑：
- 关掉后**整机防护会下降**（但 Defender 实时防护、SmartScreen 仍然在）。
- **老版 Win11：关掉后不可逆**，要重装/重置系统才能再打开；
  **较新的 Win11 版本**可以在同一页面重新打开。「评估」模式是灰的、不能手选。
- 进阶（一般用不到）：注册表
  `HKLM\SYSTEM\CurrentControlSet\Control\CI\Policy` 的
  `VerifiedAndReputablePolicyState`（DWORD，0=关 / 1=开 / 2=评估），
  改完执行 `CiTool.exe -r` 生效。手改有把 SAC 弄坏、乱拦所有程序的风险，慎用。

### 方案 B：不想关 SAC —— 借 cmd.exe 启动（免费偏方，不保证长期有效）

SAC 认为 `cmd.exe` 是可信的，用它来拉起 Yuhub 可以绕过对 exe 的直接拦截。

在 Yuhub.exe 同目录新建 `启动Yuhub.bat`：
```bat
@echo off
start "" "%~dp0Yuhub.exe"
```
双击这个 bat 即可。或者建快捷方式，目标填：
```
%windir%\system32\cmd.exe /c ""C:\Users\24270\Desktop\Yuhub.exe""
```
起始位置填 `C:\Users\24270\Desktop`。

> 这是社区偏方，实测有人可用，但**微软随时可能堵掉**，别当长期方案。

### 方案 C：向微软提交文件请求审核（免费，慢）

开发者可把 exe 提交给微软安全情报中心，申请"误报/信任"审核：
https://www.microsoft.com/en-us/wdsi/filesubmission
审核通过后该文件哈希会被信任。不可控、要等，但零成本，值得顺手做。

### ❌ 这些做法对 SAC 无效（别再试了）

- 右键「以管理员身份运行」→ 照样拦；
- 关闭 Defender 实时保护 → 没用，SAC 是独立机制；
- 在 Defender 里加「排除项」→ 没用，SAC **没有按应用例外**；
- 改文件名 / 换目录 / 压缩再解压 → 没用，SAC 按内容与签名判；
- 文件属性里「解除锁定(Unblock)」→ 只对 SmartScreen 有效，对 SAC 无用。

## 三、根治：给 exe 做代码签名（开发者侧）

SAC 的规则是「**有可信签名的程序会运行**」，所以签名是唯一长期正解。

| 方案 | 费用 | 全球可用？ | 说明 |
|---|---|---|---|
| **OV 代码签名证书**（DigiCert / Sectigo / GlobalSign） | 约 **$150–300/年** | ✅ 全球 | **首选**。SAC 放行；SmartScreen 前期可能仍提示，随发布量累积声誉后消失 |
| **SignPath Foundation** | **免费** | ✅ | 仅限**开源项目**，需申请。Yuhub 在 GitHub 上，值得先试 |
| Azure Artifact Signing（原 Trusted Signing） | ~$9.99/月 | ⚠️ **个人仅限美国/加拿大**；组织限美/加/欧/英 | 最便宜，但**中国个人用不了**（硬限制，别踩坑） |
| EV 证书 | $400+/年 | ✅ | **2024 年起不再"即时"过 SmartScreen**，和 OV 差不多，性价比低，不建议专为 SAC 购买 |
| 自签名证书 | 免费 | ❌ | **没用**：根证书不被信任，公众机器照样拦 |
| Microsoft Store 上架（MSIX） | 免费签名 | ✅ | 商店会自动重签、用户零警告；但工程量大、需过审 |

签名注意：
- 用 **RSA + SHA256**（有反馈 ECC 签名与 SAC 兼容性不好）；
- 在 CI（GitHub Actions）里用 `signtool` **构建时自动签名**每个 Release，别事后补；
- 签名后若 SmartScreen 仍提示，是"声誉未建立"，属正常，持续发版会好转。

## 四、给你的执行建议（按性价比排序）

1. **马上**：把「二、方案 A」的图文步骤发给报错用户（最快解决单机问题）；
   同时把「方案 B」当备选给出，照顾不愿关 SAC 的人。
2. **近期**：先申请 **SignPath Foundation**（免费，开源）；不通过再买 **OV 证书**（约 $150–300/年）。
3. **别买**：EV、自签名；**别选** Azure（个人中国区不可用）。
4. **发布页/README** 固定加一段本说明，减少重复答疑。

> 一句话总结：**SAC 没有"仍要运行"，单机靠关 SAC 或 cmd 启动；分发靠代码签名。**

## 五、SignPath Foundation 详解（免费签名，最值得先试）

### 它是什么

SignPath Foundation 是一个**面向开源项目的免费代码签名计划**（由代码签名公司 SignPath.io 支持）。

关键机制：**它不是 CA，不发证书给你**。它向真正的 CA 申请一张**签发给「SignPath Foundation」这个主体的证书**，然后把私钥保管在**自己的 HSM（硬件安全模块）**里，**让开源项目借用这张证书来签自己的二进制**。

所以签名后：
- 你的 exe 带**有效、可信的 Authenticode 签名**（证书链在微软信任根里）；
- **SAC 会直接放行**（SAC 的规则就是"有有效签名的应用会运行"）；
- SmartScreen 的"未知发布者/Windows 已保护你的电脑"基本消失（SignPath Foundation 本身有累积声誉）。

### 最大的代价：发布者名字变成「SignPath Foundation」

用户看文件属性 → 数字签名，会看到签名者是 **SignPath Foundation**，而不是"Yuhub"或你本人。
对多数开源项目可以接受，但你要清楚这一点（想要自己的主体名，就得买 OV 证书）。

### 申请门槛（官方 Code of Conduct，逐条）

**项目层面：**
- 不含恶意软件 / 潜在不受欢迎程序；
- 使用 **OSI 认可的开源许可证**，且**不能有商业双授权**；
- **不含专有组件**（第三方 System Library 除外）；
- **在活跃维护**；
- **已经发布**成要被签名的形态；
- **有文档**（下载页 / 商店页写清功能）；
- **需要"可验证的声誉"** —— 官方原话：不能给"没人知道源码"的程序签名；对"会被下载并执行的 exe"要求有一定声誉（库/组件豁免）。**这是最容易卡住新项目的一条**，实践中常见是等 GitHub 有几十~上百 star、有一定下载量再申请。

**行为层面：**
- 只能签**自己的项目、自己的二进制**（源码和构建脚本都得是你的）；
- **不能是黑客工具**（不得含"识别/利用漏洞、绕过运行环境安全措施"的功能）——Yuhub 的清理/内存优化/加速属正常工具，但会被人工审；
- 尊重隐私、**修改系统配置要明确告知**（Yuhub 改 hosts / 清理前有确认，符合）；
- 提供卸载方式（Yuhub 是绿色单 exe，需在文档里说明"删文件即卸载"）。

**流程层面（对个人开发者是负担）：**
- 必须定义团队角色：**Authors / Reviewers / Approvers**；
- **每个 release 的签名请求都要有人工批准**；
- 团队成员必须对 GitHub 与 SignPath 开 **MFA**；
- 项目主页/发布页要放一段固定的 **"Code signing policy"**，包含指定文案：
  「Free code signing provided by SignPath.io, certificate by SignPath Foundation」+ 角色成员 + 隐私政策。

**技术约束：**
- 二进制必须**能从源码可验证地构建**（应在 CI 里构建，而不是本地手工打包后上传）；
- 产物要设置并强制 product name / version 元数据；
- 支持签 EXE / MSI / DLL / JAR / Docker / Office 宏，支持嵌套产物。

### 申请与接入流程（约 6 步）

1. 打开 https://signpath.org/ → 「Apply for Free Code Signing」，填**仓库地址、下载页地址、项目简介、许可证**；
2. 等待人工审核（可能几天，也可能因"声誉不足"被拒）；
3. 通过后在 SignPath.io 建项目，拿到三个值：**API Token / Project ID / Policy ID**；
4. 把三个值加进 GitHub 仓库的 `Settings → Secrets and variables → Actions`；
5. 在 Release workflow 里加签名步骤（官方 Action：`signpath/github-action-submit-signing-request@v2`），流程是：
   **CI 构建 exe → 提交签名请求 → Approver 在 SignPath 界面批准 → 下载已签名产物 → 附到 Release**；
6. 首次发布前，把「Code signing policy」写进 README/发布页。

### 对 Yuhub 的适配评估

| 条件 | Yuhub 现状 | 结论 |
|---|---|---|
| OSI 开源许可 | 仓库有 LICENSE（需确认是 MIT/GPL/Apache 等） | ✅ 大概率满足 |
| 无专有组件 | `accel-framework/` 有 .cs 源码；easytier/wintun/ffmpeg 是上游 OSS | ✅ 需在申请时说明 |
| 活跃维护 + 已发布 | 持续发版、GitHub Releases | ✅ |
| 可验证声誉 | 取决于 star / 下载量 | ⚠️ **可能被卡，先攒量再申请** |
| 从源码构建 | 目前是本地 `build.bat` + PyInstaller | ⚠️ 需改成 **GitHub Actions 里构建**才算"可验证" |
| 修改系统需告知 | 清理/hosts 都有确认与说明 | ✅ |
| 非黑客工具 | 加速（本地反代 + hosts）会被人工审 | ⚠️ 需解释清楚用途 |
| 每 release 人工批准 | 低频发布 | ✅ 可接受 |
| 发布者显示 | 会变成 SignPath Foundation | ⚠️ 心理门槛 |

### SignPath vs 买 OV 证书

| | SignPath Foundation | OV 证书 |
|---|---|---|
| 费用 | **免费** | ~$150–300/年 |
| 发布者显示 | SignPath Foundation | **你自己/公司** |
| 是否要求开源 | **必须** | 不要求 |
| 声誉 | 借用 SignPath 的，较快见效 | 从零累积，前期仍提示 |
| 私钥管理 | 在他们的 HSM，你拿不到 | 你管理（云 HSM/令牌） |
| 发布流程 | 每次人工批准签名 | 你说了算 |
| 被拒/撤销风险 | 有（可随时撤销） | 无（证书归你） |

### 结论

- Yuhub 是 GitHub 上的开源项目、单 exe、正被 SAC 拦 → **SignPath 是性价比最高的第一步**，先申请试试；
- 若因"声誉不足"被拒：先攒 star/下载量、把构建搬到 GitHub Actions 再申请，或者直接买 OV；
- 若你希望签名者显示为"Yuhub"而不是别人的基金会 → 只能买 OV。
